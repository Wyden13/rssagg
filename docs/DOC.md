## Overview

**rssagg** is a RESTful API service for managing RSS feeds and user accounts. It provides endpoints for user registration, authentication via API keys, and feed management.

- **Language**: Go
- **Framework**: Chi (lightweight HTTP router)
- **Database**: PostgreSQL
- **ORM/Query Tool**: sqlc (type-safe SQL)

## Setup & Installation

### Prerequisites

- Go 1.18+
- PostgreSQL 12+
- sqlc (for code generation)

### Environment Variables

Create a `.env` file in the project root:

```env
PORT=8080
DB_URL=postgres://user:password@localhost:5432/rssagg?sslmode=disable
```

### Installation Steps

1. Clone the repository:

   ```bash
   git clone https://github.com/Wyden13/rssagg.git
   cd rssagg
   ```

2. Install dependencies:

   ```bash
   go mod download
   go mod vendor
   ```

3. Set up the PostgreSQL database and run migrations:

   ```bash
   # Create the database
   createdb rssagg

   # Run migrations (if available)
   # psql -U user -d rssagg -f sql/schema/001_users.sql
   ```

4. Generate sqlc code from SQL queries:

   ```bash
   sqlc generate
   ```

5. Build the project:

   ```bash
   go build -o rssagg
   ```

6. Run the server:
   ```bash
   ./rssagg
   ```

The server will start on the port specified in `PORT` (default: 8080).

```json
  "updated_at": "2026-03-21T10:30:00Z",
  "api_key": "abcd1234efgh5678ijkl9012mnop3456"
```

**Response** (400 Bad Request):

```json
{
  "error": "Failed to decode request body: ..."
}
```

**Response** (500 Internal Server Error):

```json
{
  "error": "Failed to create user: ..."
```

## Database Schema

### Users Table

```sql
CREATE TABLE users (
    id UUID PRIMARY KEY,
    username VARCHAR(255) NOT NULL UNIQUE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    api_key TEXT UNIQUE NOT NULL
);
```

| Column     | Type         | Constraints      | Notes                               |
| ---------- | ------------ | ---------------- | ----------------------------------- |
| id         | UUID         | PRIMARY KEY      | Unique user identifier              |
| username   | VARCHAR(255) | UNIQUE, NOT NULL | User's display name                 |
| created_at | TIMESTAMP    | DEFAULT NOW()    | Account creation time               |
| updated_at | TIMESTAMP    | DEFAULT NOW()    | Last account update time            |
| api_key    | TEXT         | UNIQUE, NOT NULL | Auto-generated API key using SHA256 |

## Authentication

### API Key Authentication

All authenticated endpoints require an API key passed in the `Authorization` header:

```
Authorization: Bearer <api_key>
```

### API Key Generation

When a user is created, an API key is automatically generated using:

```sql
encode(sha256(random()::text::bytea), 'hex')
```

This ensures each user has a unique, secure API key.

### Authentication Middleware

The `middleware_auth.go` file contains middleware that can be applied to routes requiring authentication. It:

1. Extracts the API key from the `Authorization` header
2. Retrieves the user from the database using `GetUserByAPIKey`
3. Passes the user context to the handler

## Error Handling

### Error Response Format

All errors follow a consistent JSON format:

```json
{
  "error": "Descriptive error message"
}
```

### Common Error Codes

| Status | Code                  | Meaning                            |
| ------ | --------------------- | ---------------------------------- |
| 200    | OK                    | Request successful                 |
| 400    | Bad Request           | Invalid request body or parameters |
| 403    | Forbidden             | Missing or invalid API key         |
| 500    | Internal Server Error | Server error                       |

### Error Handler

The `handler_err.go` file provides:

- `respondWithError()` - Send error responses with HTTP status and message
- `respondWithJSON()` - Send success responses with JSON data

## Development

### Running Tests

```bash
go test ./...
```

### Adding New Endpoints

1. Create a new handler in a dedicated file (e.g., `handler_feeds.go`)
2. Add SQL queries in `sql/queries/` directory
3. Regenerate code with `sqlc generate`
4. Register the route in `main.go`

### Adding Database Queries

1. Add SQL query to appropriate file in `sql/queries/`
2. Use the `-- name: QueryName :one` or `:many` comment format
3. Run `sqlc generate` to generate Go code
4. Use the generated method in your handlers

### Code Generation Workflow

```bash
# Edit SQL queries
vim sql/queries/users.sql

# Regenerate Go code
sqlc generate

# Build and test
go build
go test ./...
```

```bash
go get -u ./...

```

## CORS Configuration

The API is configured with CORS enabled for:

- **Allowed Origins**: `https://*`, `http://*` (all origins)
- **Allowed Methods**: GET, POST, PUT, DELETE, OPTIONS
- **Allowed Headers**: All headers
- **Max Age**: 300 seconds

This is configured in `main.go` using the `go-chi/cors` middleware.

## Troubleshooting

### Database Connection Error

- Ensure PostgreSQL is running
- Check `DB_URL` in `.env` file
- Verify database exists: `psql -l | grep rssagg`

### Port Already in Use

- Check if port is in use: `lsof -i :8080`
- Kill process or change `PORT` in `.env`

### Migration Issues

- Ensure schema is applied: `psql -d rssagg -f sql/schema/001_users.sql`
- Check for migration conflicts

### sqlc Code Generation Issues

- Ensure `sqlc.yaml` is properly configured
- Check SQL query syntax
- Verify table names match schema
